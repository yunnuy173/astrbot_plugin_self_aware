# 能力自省 (astrbot_plugin_self_aware)

让 bot **认识、理解并使用**自己的能力——包括那些**根本没写命令**的插件。

装了一堆插件，bot 却不知道"我能唱歌""我能发表情包"——被问就装傻，该用时想不到。
这个插件把"你会什么"变成它真正能用的东西，并且让它做完之后知道自己做了什么。

## 安装 / 快速开始

1. 把整个 strbot_plugin_self_aware 目录放进
   AstrBot的数据目录/plugins/（WebUI 里也能直接上传 zip）。
2. 重启 AstrBot，或在 WebUI 插件页重载本插件。
3. 打开插件配置，确认这三项是开的：语义直连、自动画像、工具直连（默认都开）。
4. 在聊天里发一次 /能力 刷新：它会扫描本机所有插件，并开始给每个插件写能力画像
   （第一次要一两分钟，每个插件一次模型调用）。
5. 之后正常聊天即可。想看她学到了什么，去 WebUI 插件页的「能力面板」。

依赖：AstrBot 4.16+。不需要额外安装任何 Python 包。

## 它解决的四个问题

| 问题 | 做法 |
|---|---|
| **不知道自己会什么** | 运行时能力表：读 AstrBot 注册表的指令 + `llm_tools` 里的工具 + 插件说明，而不是扫文件夹猜 |
| **不知道什么时候用** | 语义匹配 + 能力画像里「用户会怎么说」的样例，只注入相关的那几条 |
| **不知道该怎么用** | 命令带参数说明，工具带参数 schema |
| **干完了不知道** | 每次命中/执行写进思考流；工具调用成功或失败都留原因 |

## 能力表：三类入口

| 入口 | 来源 | 怎么用 |
|---|---|---|
| 命令 `@filter.command` | `star_handlers_registry` | 转成该命令直接执行 |
| 工具 `@llm_tool` | `llm_tools.func_list` | 直接调用 handler，或被模型自己调 |
| 源码兜底 | AST 扫 `main.py` | 上面两样都拿不到时才用 |

所以像表情包管理器这种"没有 `/发表情` 命令、只注册了工具"的插件，也在能力表里。

## 能力画像（v2.4）

给每个插件生成一张「能力卡片」，LLM 分析一次，之后按指纹缓存：

```
plugin_data/astrbot_plugin_self_aware/profiles/<插件名>.json
```

```json
{
  "what": "按心情挑一张表情包发出去",
  "when": ["聊到情绪时", "想要一张反应图时"],
  "examples": ["发个开心的表情包", "来个震惊的表情"],
  "avoid": ["查一下MC皮肤"],
  "limits": ["不能改图"],
  "entry": [{"kind": "tool", "name": "send_meme", "params": ["target"]}]
}
```

- **只分析变过的**：指纹 = 描述 + 入口清单 + `metadata.yaml`/`main.py` 修改时间
- **五个触发点**：启动后分批补 3 个；装新插件时后台补 1 个；说「去看看我装的新功能」现场分析；`/能力 刷新` 全量；WebUI 插件页的**能力面板**里点「分析」
- **失败不卡住**：重试一次，还不行就用插件说明顶着，并标记下次再试
- **只喂素材不喂源码**：插件描述、命令、工具参数；生成的是什么就存什么，可以手动改 json

画像里的 `examples` 会进匹配语料，比作者写的插件简介更贴近真人说法。

## 简易说明书

识别插件之后顺手生成一份人话说明书，存在 `manuals/<插件名>.txt`：

```
【表情包管理器】按心情挑一张表情包发出去
什么时候用：聊到情绪时；想要一张反应图时
这样说就行：
  · 发个开心的表情包
  · 来个震惊的表情
命令：
  · /查看图库
工具（她自己能调）：
  · send_meme（参数 target）
做不到：不能改图
```

问她「表情包怎么用」「XX 有什么功能」，她直接把这份发出来。也可以用
`/能力 说明书` 看有哪些、`/能力 说明书 <名字>` 单独看一份。

### 插件更新了怎么办

不用手动管。每个插件都算了指纹（描述 + 入口清单 + `metadata.yaml`/`main.py` 的修改时间）：

- 插件更新后重新加载 → 指纹变了 → 画像和说明书自动重写，日志里会留一行「插件有变化，画像和说明书已重写：xxx」
- 更新发生在 bot 没运行的时候 → 下次启动时补上（启动后分批，每次 3 个）
- 想知道哪些过时了：`/能力 过时`；想立刻全部重写：`/能力 刷新`

## 语义直连

不用打命令，说话就行。执行顺序：

```
自动规则 → 通用推导 → 工具直连 → 内建规则 → 通用兜底 → 模型选指令
```

### 先过闸门

这几种一律不猜：

- 超过 40 字（以「发/来/给/找/搜/唱/点/查/看/念/帮…」开头的放宽到 80 字）
- 含换行、引用、`[图片]`、合并转发标记
- 已经以 `/` 开头、bot 自己的消息

原因很实在：QQ 的引用和合并转发会把整段聊天记录塞进 `message_str`，拿去当命令参数就是灾难。

### 参数要洗

所有路径共用一套清洗：去掉 `@昵称(QQ号)`、`[引用了…]`、`【】`提示块、括号解释、转发边框，压空白，截断长度。

## 工具直连

对"有工具没命令"的插件：

- 从命中的能力里挑工具，按「发/搜」这类意图排序（说"来个表情"不会变成"搜表情"）
- 只给**单参数**工具自动填参，多参数的不猜
- 先试一次（12 秒），成了才拦下这条消息
- 失败就**放行**，让这条消息照常走模型，由插件按它的规矩调工具
- 遇到 `tool_unavailable` 这类「依赖请求期准备」的工具，记进 `tool_state.json`，以后不再白试

`/能力 工具` 看状态，`/能力 重置工具` 清空。

## 命令

| 命令 | 作用 |
|---|---|
| `/能力` | 列出全部能力 |
| `/能力 <关键词>` | 搜索相关能力 |
| `/能力 刷新` | 重扫插件 + 重写变过的画像和说明书 |
| `/能力 说明书 [名字]` | 简易说明书（不给名字就列清单） |
| `/能力 工具` | 运行时工具表和不直连名单 |
| `/能力 过时` | 哪些插件的画像/说明书该重写了 |
| `/思考流 开\|关\|最后 3\|清空` | 思考流 |
| `/推理 关\|低\|中\|高` | 推理档位 |
| `/余额` | 查余额 |
| `/日志 30` | 看运行日志 |

> `/自兼容 生成` 是早期那套「让模型写正则」的机制，现在画像和语义匹配已经覆盖大部分场景，
> 默认不需要；只在某个插件怎么都触发不对时才值得一试。

## 配置（主要几个）

设置页里的顺序就是下面这个顺序，越前面越常改：

| 键 | 默认 | 说明 |
|---|---|---|
| `auto_dispatch` | `true` | 说话就直接执行（总开关） |
| `auto_profile` | `true` | 自动写画像和说明书 |
| `tool_dispatch` | `true` | 没有命令的插件也能用 |
| `inject_mode` | `semantic` | 每次给她看多少能力 |
| `match_threshold` | `1.2` | 匹配严格度，误触发就调高 |
| `llm_route` | `true` | 规则不中时让模型挑一条指令 |
| `generic_dispatch` | `true` | 通用兜底（靠命令名和说明猜） |
| `builtin_rules` | `false` | 内置写死规则（歌/图/梗），默认关 |
| `capture_logs` | `true` | 记录运行日志 |
| `merge_thought` | `true` | 能力命中写入思考流 |

完整 30 项见 `_conf_schema.json`，每项都带一句人话说明。

## 能力面板（WebUI）

插件页里只有一页「能力面板」，里面两个标签页：

**插件**
- 每个插件一行：她的理解（画像里的 `what`）、命令/工具数量、是否过时、有没有说明书
- 三个按钮：**分析新插件**（只处理过时的）、**全部重写**（每个插件都重跑一次模型）、**刷新**
- 点任意一行看它的简易说明书
- **清理日志**：删掉 `logs/` 和 `thoughts/`
- **一键重置**：删掉能力表缓存、全部画像、全部说明书、工具黑名单，然后重新扫描（画像要重新分析）

**思考流**
- 左边文件列表、右边内容；可以在线切换推理档位、清空记录

> 说明：AstrBot 的侧边栏只显示每个插件的**第一个**页面（`pages[0]`），
> 所以多个页面会被藏进二级分组。这里干脆合成一页，省得找不到。

## 数据目录

```
<AstrBot 数据目录>/plugin_data/astrbot_plugin_self_aware/
  self_aware_caps.json    能力表缓存（带指纹）
  profiles/<插件>.json     能力画像
  manuals/<插件>.txt       简易说明书
  auto_rules.json          自兼容规则
  tool_state.json          不直连的工具
  thoughts/YYYY-MM-DD.log  思考流
  logs/YYYY-MM-DD.log      运行日志
```

## 跨会话

你在私聊里说「去群里发个表情包」「去群里说声晚安」时，她上下文里会自动多一段跨会话能力清单，
并且她有一个工具可以在**目标会话里执行**：

```
run_capability(command="点歌", args="海底", target="123456789")
```

`target` 填群号（或完整会话标识），命令就**在那个群里执行**——不是在这儿做完再转发过去。
没填 target 就是当前会话。

清单是按命令说明里有没有「群 / 传话 / 转发 / 记录」自动凑出来的，按插件轮着取，
句子里提到「图 / 表情」时带图的入口排前面。目的是让她别再说「我做不到」。

## 出错了会怎样

自动执行没成功时，她不会装没事：

1. 先记下失败原因（异常、返回值、`reason` 字段都会留）
2. 如果 `diagnose_failure` 开着，读最近的运行日志，让模型判断可能原因，回两三句人能看懂的话
3. 诊断不出来就退回到一句「没弄成……（原因）」，不会静默

日志来源就是插件自己在 `logs/` 里记的那份，所以**`capture_logs` 关掉的话诊断会失去依据**，只会给通用回答。

## 安全边界
- 危险指令不暴露、不执行：删除 / 清空 / 重置 / 重启 / 关闭 / 配置 / 权限 / 踢 / 禁言 / 撤回 / 卸载…
- 每条消息只处理一次，不会循环
- 指代（这个/那个/啥）不猜
- 工具调用有超时、有失败回落，不会把消息吞掉

## 兼容性

- AstrBot 4.16+
- 依赖三个内部接口（注册表、`llm_tools`、`star_map`），都做了降级：拿不到就少一层能力，不会崩
- 与"概率筛选""主动发言"类插件可以共存；有些陪伴核心会清理别的插件注入的内容，注入不生效可以先关掉对方的清理
